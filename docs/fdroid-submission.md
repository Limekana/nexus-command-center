# F-Droid Submission — Build Recipe & MR Notes

Reference for the Limecore suite's F-Droid inclusion. Covers the three
`fdroiddata` merge requests, the build recipe each uses, the self-hosted-font
work, and the review fixes applied. Read this before bumping a version or
touching the recipe — several settings look redundant but exist to satisfy the
reviewer or the reproducible-build check.

## Build recipe (per app)

The `Builds:` entry each app uses in its `fdroiddata` metadata:

```yaml
Builds:
  - versionName: <x.y.z>
    versionCode: <n>
    commit: <FULL 40-char commit hash of the release tag>   # NOT the tag, NOT the tag object
    subdir: android/app
    sudo:
      - echo "deb https://deb.debian.org/debian forky main" > /etc/apt/sources.list.d/forky.list
      - apt-get update
      - apt-get install -y -t forky nodejs npm
    init:
      - cd ../..
      - npm ci
    gradle:
      - yes
    prebuild:
      - cd ../..
      - npm run build
      - npx cap sync android
    scandelete:
      - node_modules
```

Key points:

- **Node.js comes from Debian forky**, installed with apt (`-t forky` scopes
  the pull to just `nodejs`/`npm`). This replaced an earlier approach that
  `curl`-downloaded a Node tarball from nodejs.org — F-Droid prefers a distro
  package, forky (Debian testing) carries a new-enough Node 22, and it
  sidesteps the buildserver having no `xz`.
- **`init`/`prebuild` `cd ../..`** because `fdroidserver` runs the recipe from
  the `android/app` subdir, but `npm`/`cap sync` must run from the repo root.
- **`scandelete: node_modules`** removes build-only binaries the scanner flags.

## Self-hosted fonts (offline-safe, F-Droid requirement)

**Do not load fonts from `fonts.googleapis.com`.** A `<link rel="stylesheet">`
to Google Fonts in `index.html` is render-blocking: on a device that can't
reach Google (offline, or an F-Droid user who firewalls Google) the WebView's
first paint stalls on the request and the app hangs on the native splash.
F-Droid also disallows the third-party Google call outright.

All three apps self-host their fonts under `public/fonts/`, declared via
`@font-face` with `font-display: swap`, with the Google `preconnect`/stylesheet
links and the `fonts.googleapis.com`/`fonts.gstatic.com` CSP entries removed.

| App | Fonts | How it was done |
|---|---|---|
| NCC | Space Grotesk + Inter (variable woff2) | `@font-face` in `src/index.css`; CSP `style-src`/`font-src` trimmed |
| LimeLog | Barlow + Barlow Condensed (static woff2) | limelog PR #1 |
| StudyDesk | DM Sans, DM Mono, Playfair (static woff2) | already self-hosted (`public/fonts/fonts.css`) |

Notes:

- NCC's fonts are the **same variable woff2 files Google served** (Space Grotesk
  wght 300–700, Inter wght 100–900), so rendering is byte-identical to before —
  `@font-face` just uses a `font-weight` range instead of per-weight files.
- `android/app/src/main/assets/public` is gitignored (regenerated by
  `npm run cap:sync`), so bundling only needs the files under `public/fonts/`;
  the next sync copies `dist/` (fonts included) into the APK.

## Reproducible builds

Each metadata file sets `Binaries:` (pointing at the signed APK on the matching
GitHub release tag) and `AllowedAPKSigningKeys`. F-Droid rebuilds from source
and compares against the published APK, so the build must be byte-for-byte
reproducible.

- Signed release APKs are published on GitHub Releases at each pinned tag
  (`v%v` in the `Binaries:` URL resolves to the release asset).
- All three apps share one signing certificate:
  `27e17d1fba157da6eacde58485aab56066200cc45ad00bd518d828367ec155e4`.
- **Node source does not affect reproducibility.** The JS bundle is pinned by
  `package-lock.json` (Vite/rollup/esbuild) via `npm ci`, not by the Node
  runtime — switching the tarball for forky's Node kept `fdroid build` green.
- `check apk` also requires the AGP dependency-metadata signing block disabled
  in the app (`dependenciesInfo { includeInApk false }`), so no unreproducible
  dependency-metadata blob lands in the APK.

## `commit:` must be the commit, not the tag object

`commit:` must be the **dereferenced commit hash**. For an *annotated* tag,
`git ls-remote <repo> refs/tags/<tag>` returns the **tag object** SHA, which is
*not* the commit. Always dereference:

```sh
git ls-remote <repo> "refs/tags/<tag>^{}"   # ^{} → the commit the tag points to
```

The build resolves either form, but the reviewer requires the commit hash. This
was flagged after an earlier round pinned the tag objects by mistake.

## `AntiFeatures: NonFreeNet` — reason required

`NonFreeNet` must carry a reason in **map form** (not a bare `- NonFreeNet`
list), and the reason must actually describe the network behaviour, including
**third-party AI processing** of user content where it applies:

```yaml
AntiFeatures:
  NonFreeNet:
    en-US: <what the app connects to and why it's flagged>
```

Per-app reason (each names only its own services):

- **NCC:** Supabase (cloud sync), Google (sign-in), third-party finance data
  providers, and a hosted AI service.
- **StudyDesk:** Supabase (cloud sync), Google (sign-in), and a hosted AI
  service.
- **LimeLog:** needs to state Supabase (cloud sync), Google (sign-in), **and
  that the AI-debrief feature sends workout-note text to a hosted AI service
  (Gemini)** — "cloud sync" alone doesn't convey third-party AI processing of
  note content. (Update queued with the v1.8.3 metadata bump; see below.)

## Checklist when releasing a new version

1. Merge the change to `main`; build, sign, and publish the APK as a GitHub
   Release asset matching the `Binaries:` URL pattern.
2. In `fdroiddata`, add/replace the `Builds:` entry with the new
   `versionName` / `versionCode` and the **dereferenced commit hash**
   (`git ls-remote <repo> "refs/tags/<tag>^{}"`).
3. Keep the `AntiFeatures: NonFreeNet` reason map — do not let a rewrite drop it
   to a list.
4. Keep Node coming from forky; keep fonts self-hosted (no Google Fonts links).
5. Update `CurrentVersion` / `CurrentVersionCode`.
6. Push to the MR branch; confirm the pipeline is green (`fdroid build`,
   `check apk`, `fdroid lint`, `fdroid rewritemeta`) before pinging the reviewer.
